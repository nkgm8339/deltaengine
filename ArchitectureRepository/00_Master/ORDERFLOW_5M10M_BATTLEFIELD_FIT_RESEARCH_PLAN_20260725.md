## 0. 最上位の問い

本研究が最初に答える問いは、5M・10M機能をどう実装するかではない。

> 1M戦場向けに作られたDeltaEngineのオーダーフロー原理は、  
> 5～10分にわたる攻防でも方向優位性を持つのか。  
> それとも1Mだから成立する短命な現象なのか。

HFMのスプレッドを越えられる時間軸を先に選び、既存1Mロジックをそこへ
引き伸ばしてはならない。

検証順序は、必ず次のとおりとする。

1. Binance内で5～10分のオーダーフロー構造が存在するか
2. その構造が未知期間でも再現するか
3. Binanceで観測した構造がHFM価格へ伝達するか
4. HFMの実Bid／Ask、遅延、滑り、手数料を含めても成立するか
5. 上記を通過してから、ライブ実装方式を決める

## 1. この研究でいう5M・10M

5M・10Mは、最初から固定ローソク足や固定保有時間を意味しない。

観測解像度はRAW約定、秒窓、1Mを維持する。そのうえで、
一つの攻防を5～10分まで連続追跡する。

```text
買い攻撃
  → 価格非反応・停滞
  → 買い攻撃の継続
  → 攻撃側または受動側の失速
  → 上または下への解放
```

売り側も完全に対称に扱う。

これは「5分足を作る」ことではなく、複数の短時間状態を順序付きの
オーダーフロー・エピソードとして扱うことである。

UTCの5分・10分境界は、攻防の開始時刻ではない。固定足集計は比較対象にはするが、
エピソードの主境界にはしない。

## 2. 二つの仮説を分離する

### 仮説A: 複数状態の攻防エピソード

1M以下の解像度で観測した攻撃、停滞、継続、失速、解放の順序に、
5～10分先の価格経路を説明する情報がある。

これは本研究の本命仮説である。

### 仮説B: 1Mロジックの固定時間保有

既存1M状態で入り、根拠の継続と無関係に5分・10分保有する。

これは本命ではなく、比較用の対照仮説とする。長く保有するだけでは優位性は増えず、
1M優位性の消滅後に無関係な価格変動へさらされる可能性があるためである。

仮説Aが仮説Bを上回らなければ、「攻防観測を延ばす」新設計の意味は確認できない。

## 3. オーダーフロー・エピソードの暫定状態機械

閾値はこの計画書で決め打ちしない。先に状態と意味を固定し、数値閾値は
学習期間の分布だけで決め、検証期間では変更しない。

### E0: NEUTRAL

同方向の攻撃が開始していない通常状態。

### E1: AGGRESSION

BUYまたはSELLの成行約定が相対的に優勢になった状態。

最低限記録するもの:

- 攻撃側
- aggressive volume
- Delta
- pressure ratio
- relative volume
- 開始時刻

### E2: NON_RESPONSE

攻撃量に対して価格が十分に追随していない状態。

単なる値幅の小ささではなく、圧力に対する価格反応率として扱う。

### E3: SUSTAINED_CONFLICT

同方向の攻撃と価格非反応が、許容gap内で複数回続いた状態。

最低限記録するもの:

- 継続時間
- 同方向攻撃の累積量
- 攻撃中断時間
- 価格反応率の推移
- STALLED／TRAPPED／EFFECTIVEの遷移順
- Footprint／Imbalance／Absorptionの同時刻観測

### E4A: AGGRESSOR_BREAKTHROUGH

受動側流動性が耐えられず、価格が攻撃方向へ解放された状態。

### E4B: DEFENDER_REVERSAL

攻撃側が失速または捕まり、価格が攻撃と反対方向へ解放された状態。

### EX: INVALIDATED／DATA_GAP

次の場合はエピソードを終了または無効化する。

- 反対側攻撃が優勢になった
- 同方向圧力の継続条件が切れた
- データgapをまたいだ
- 非正値・非有限の価格または数量が含まれた
- 最大観測時間を超えても決着しなかった

未決着を勝ち・負けへ強制分類しない。

## 4. 観測チェックポイント

後から見た決着を入口へ混ぜないため、同じエピソードに複数の
因果的チェックポイントを持たせる。

1. `T_ATTACK`: 攻撃開始を観測できた時刻
2. `T_STALL`: 価格非反応を初めて確認できた時刻
3. `T_PERSIST`: 継続条件を初めて満たした時刻
4. `T_RESOLVE`: 攻撃側または受動側への解放を確認できた時刻

各チェックポイントの特徴量は、その時刻以前の情報だけで作る。

これにより、早いが不確実な入口と、遅いが決着に近い入口を分けて比較する。

## 5. 事後ラベル

各チェックポイントから、最低限次を保存する。

- 1分、3分、5分、10分後の価格変化
- 5分、10分内のMFE／MAE
- MFEとMAEのどちらが先に発生したか
- 解放方向
- 解放までの秒数
- 解放前の最大逆行
- 5分・10分時点で未決着か
- 同じ攻防の重複イベントか

15分・30分は優位性の減衰確認用にだけ保存できる。
長時間足での売買を前提にしない。

## 6. 独立標本の規則

ローリング窓の連続更新を、独立した勝負として数えない。

- 一つの連続攻防に一つの`episode_id`を付ける
- 30s、1m、3m、5mなど同じ約定を含む窓を独立票にしない
- 同一エピソード内の複数チェックポイントを独立標本数へ足さない
- 同時保有を許さない比較では、時間重複する候補をpurgeする
- 日単位または連続セッション単位のblock bootstrapを使う
- データgapをまたぐエピソードは破棄し、補間しない

## 7. 研究フェーズと判定ゲート

### Phase 0: データ完全性

目的:

- RAW約定を重複・欠落監査できる
- 連続観測区間を明示できる
- 既存1MイベントをRAWから再現できる範囲を識別する
- HFM quoteの時刻、sequence、Bid、Askを連続保存できる

成果物:

- データmanifest
- 連続区間とgap一覧
- clean boundary
- 除外理由別件数

Gate 0:

データgap、再起動、重複、非正値を黙って含めず、各エピソードの再現元を
追跡できること。

### Phase 1: Binance内の構造確認

目的:

- エピソード状態機械をオフラインで構築する
- AGGRESSOR_BREAKTHROUGHとDEFENDER_REVERSALを分ける
- 5分・10分の価格経路が、同条件の通常時刻と異なるか確認する

比較対象:

- 時刻帯と直前volatilityを合わせた無作為時刻
- 単発STALLED／TRAPPED
- 既存1M状態の固定5分・10分保有
- 固定5m／10m Native Flow
- 順序付きエピソード

Gate 1:

順序付きエピソードが、未知期間でも比較対象より一貫した価格経路差を持つこと。
平均終値だけでなく、MFE／MAEの順序と解放までの時間にも差があること。

ここで差がなければ、HFMコスト評価へ進まない。

### Phase 2: 時間的再現性

方法:

- chronological train／validation／untouched test
- 最大Outcome時間以上のembargo
- 閾値と状態遷移規則はtrainだけで固定
- test結果を見て条件を追加しない
- 相場方向、volatility、JST時間帯、曜日で層別
- OIは独立コンテキストとして層別し、単一scoreへ混ぜない

最低蓄積条件:

- 最終的な実用候補判定は30日以上
- 重複除去後200エピソード以上
- 一日だけの利益が全正利益の25%を超えない

上記未満でも計算器の検証はできるが、優位性を宣言しない。

Gate 2:

- untouched testで効果方向が維持される
- 日またはセッション単位bootstrapの95%下限が0を上回る
- 特定の一日・一時間帯だけで結果が作られていない
- trainとtestで解放までの時間分布が極端に変わらない

### Phase 3: BinanceからHFMへの伝達

目的:

Binanceで観測したエピソードが、HFM BTCUSDの価格経路にも同じ向きと時間で
現れるか確認する。

必須規則:

- Binanceイベント後に観測できたHFM quoteだけを入口候補にする
- source timeとreceived timeを両方保持する
- BUYはAskで入り将来Bidで出る
- SELLはBidで入り将来Askで出る
- Bid／Askへスプレッドが内包されている場合、別途二重控除しない
- quote gap、stale、sequence gapを明示する
- 1秒、3秒、5秒の遅延条件を分ける
- Binance／HFM間のbasis変化を別項目にする

Gate 3:

Binance内の価格経路差がHFMでも同方向に再現し、HFMで観測不能な短命現象だけに
依存していないこと。

### Phase 4: HFM実コスト成立性

評価:

- 実Bid／Askによるnet PnL
- 実測spread分布
- 実測slippage
- 手数料
- 1.5倍cost stress
- MFE／MAEと決着順
- 最大連敗、最大drawdown

Gate 4:

- untouched testのnet期待値が正
- cost stress後も95%下限が正
- 利益が少数の外れ値だけで作られていない
- 現実的な逆行幅と保有時間で執行可能

ここを通過するまで売買発注機能を作らない。

## 8. Gate通過後の実装分岐

### 結果A: 順序付きエピソードだけが成立

RAW／1M解像度の上に、イベント時間型のEpisode Engineを追加する。
固定5m／10m足をエントリーの主判定にはしない。

### 結果B: 固定5m／10m Native Flowが成立

Native Execution基盤を候補にできる。ただし現在の単純な
Delta符号×始終値判定を完成ロジックとは扱わず、検証で確認された構造へ置き換える。

### 結果C: Binanceでは成立、HFM netでは不成立

DeltaEngineをHFMへ無理に合わせない。執行先不適合として停止する。

### 結果D: Binanceの5～10分構造自体が不成立

5M・10M実装を停止する。1M用DeltaEngineの完成範囲を維持する。
