# DeltaEngine座学 第7講 — 板・スプレッド・流動性

作成日: 2026-07-21  
対象: 約定系指標とAbsorptionを理解した人  
テーマ: 約定前の待機注文と、価格が動きやすい地形を読む

---

## この講義のゴール

1. Bid、Ask、best bid、best askを説明できる
2. スプレッドの式と急拡大の意味を説明できる
3. 板の厚さと実際の約定を分けて考えられる
4. Snapshot、Diff、sequence gapの必要性が分かる
5. 板と3段チャートを同じ時刻で比較できる

最も大切な一文はこれ。

> **板は「待っている注文」、Footprintは「成立した約定」。両方を同じ時刻で比べる。**

---

## 1. 板が表すもの

Order Bookは、まだ約定していない指値注文の一覧である。

### Bid

この価格なら買いたいという待機注文。

### Ask

この価格なら売りたいという待機注文。

通常、価格に最も近い注文をbestと呼ぶ。

```text
best bid = 最も高い買い指値
best ask = 最も安い売り指値
```

買い成行はbest ask側から食べ、売り成行はbest bid側から食べる。

---

## 2. スプレッド

スプレッドは次の差である。

```text
spread = best ask - best bid
```

例:

```text
best bid = 100.0
best ask = 100.1
spread   = 0.1
```

スプレッドが狭いと、売買の最前線が近い。
急に広がると、最良気配が消えた、移動した、または片側が薄くなった可能性がある。

ただし、スプレッド拡大だけで方向は決まらない。
best bidとbest askのどちらが動いたかを確認する。

---

## 3. 3つのスプレッド拡大

### Askが上へ飛ぶ

```text
best bid: 100.0 → 100.0
best ask: 100.1 → 100.5
```

売り板の手前が薄くなった可能性。
上方向へ動きやすい地形かもしれない。

### Bidが下へ落ちる

```text
best bid: 100.0 → 99.6
best ask: 100.1 → 100.1
```

買い板の手前が弱くなった可能性。
下方向へ動きやすい地形かもしれない。

### 両方が離れる

```text
best bid: 100.0 → 99.8
best ask: 100.1 → 100.3
```

両側の流動性が引いた可能性。
方向よりも、価格が飛びやすい不安定さを疑う。

いずれも「可能性」であり、約定の発生を確認する。

---

## 4. 板の厚さ

数量の大きい価格帯は壁のように見える。

しかし板の注文は、約定前に取消・移動され得る。

したがって、次を分ける。

```text
板に見えた      = 待機注文が表示された
約定した        = 実際に取引が成立した
補充された      = 食われても数量が維持・回復した
価格を止めた    = 結果として価格が進まなかった
```

本当に重要なのは、表示された大口注文の存在だけでなく、
成行を受けても残ったか、補充されたか、価格を止めたかである。

---

## 5. SnapshotとDiff

取引所から板全体を毎回受け取るのではなく、通常は次の2種類を組み合わせる。

### Snapshot

ある時点の板全体の基準状態。

### Diff

基準状態から追加・変更・削除された差分。

```text
Snapshot
  + Diff 1
  + Diff 2
  + Diff 3
  = 現在の板
```

差分には順番がある。一つ抜けると、それ以降の板が誤る可能性がある。

---

## 6. Sequence gap

更新IDが連続しなければgapである。

```text
受信: 100 → 101 → 103
欠落: 102
```

DeltaEngineはgapを検出すると、その差分をそのまま信じ続けず、再同期が必要な状態として扱う。

板分析の前に確認すること:

- 初期Snapshotが適用済みか
- gapが発生していないか
- 再同期が完了しているか
- 比較する時刻の板が信頼できるか

壊れた板を精密に分析しても、結論は精密にならない。

---

## 7. DeltaEngineの板レビュー用データ

2026-07-22の監査で、旧録画には初期Snapshotが含まれず、全2,939行が
`depthUpdate`差分であることが判明した。`clean_strong`はさらに数量0、
つまり板levelの削除命令を除去していた。

したがって、旧3録画と旧`spread_jumps.jsonl`／`spread_jumps.csv`は
研究へ使用しない。

正しい板レビューは次の順で作る。

1. REST `depthSnapshot`を録画へ保存する。
2. その後の数量0を含む連続`depthUpdate`を板状態へ適用する。
3. gap発生後は新しいSnapshotまで集計しない。
4. 同期済み状態のbest askとbest bidからspreadを計算する。
5. 上位5段はbidを価格降順、askを価格昇順に並べる。

```text
spread = best ask - best bid
spread_ma5 = 直近5点のspread平均
spread_jump = spread - spread_ma5
```

既定の抽出閾値:

```text
spread_jumpの平均 + 2 × spread_jumpの標準偏差
```

出力:

```text
spread_jumps.jsonl
spread_jumps.csv
```

新しい同期録画から再生成されたものだけがレビュー候補になる。
旧10件は異常候補ではなく、誤った板復元方法の保存記録である。

---

## 8. 板と3段チャートを合わせる

同じ時刻で次の順に確認する。

1. PRICE: 実際に上がったか、下がったか
2. CVD: 累積の積極売買はどちらか
3. Delta: 直近バーはどちらか
4. Volume: 参加量が大きいか
5. Flow Response: 圧力は有効・停滞・逆行のどれか
6. Board: best bid/askの移動と上位5段の厚さ
7. Footprint/Imbalance/Absorption: 約定場所と受け止め

時刻がずれると、原因と結果を逆に結び付ける危険がある。

---

## 9. 例 — 買い圧力があるのに下落

```text
価格: 下落
CVD: 上昇
Delta: プラス
Flow: BUY_TRAPPED
板: best bidが下へ移動、上位Bid数量も減少
```

観測事実:

- 買い成行優勢
- それでも価格下落
- 買い板の手前が弱くなった

仮説:

- 買い成行以上に、Bid側流動性の撤退が価格へ影響した
- Ask側に見えにくい補充があった

断定には、時系列の板更新と実際の約定をさらに確認する。

---

## 10. よくある誤読

### 大きな買い板があるから上がる

誤り。買い板は価格の下側にあり、下落を受け止める候補。上昇を直接発生させる買い成行ではない。

### 大口板は必ず約定する

誤り。取消・移動され得る。

### スプレッド拡大は下落

誤り。どちら側が動いたかで背景が異なる。

### spread jump一覧は異常確定

誤り。統計的な候補抽出であり、各行を板と価格でレビューする。

### 板だけで相場を読める

誤り。待機注文と実約定、価格反応を結び付ける必要がある。

## 12. 確認問題と解答

1. spreadの式は何か。  
   **答え:** best ask - best bid。
2. 板とFootprintの違いは何か。  
   **答え:** 板は未約定の待機注文、Footprintは約定済み数量。
3. Askだけ上へ飛んだとき何を疑うか。  
   **答え:** 手前の売り板が薄くなった可能性。
4. sequence gapが危険なのはなぜか。  
   **答え:** 差分が欠けると現在の板状態が正しく再現できないから。
5. spread jump候補を見つけた後は何をするか。  
   **答え:** best bid/ask、上位板、約定、価格、CVD、Delta、Flowを同じ時刻で確認する。
