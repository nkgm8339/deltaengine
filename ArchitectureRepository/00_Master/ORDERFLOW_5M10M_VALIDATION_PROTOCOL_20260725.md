# 5M/10M Orderflow Validation Protocol

制定日: 2026-07-25  
目的: 1Mで観測している注文フローのEpisode構造が、5M/10Mの観測時間でも保持され、HFMのコスト環境で検証可能かを判定する。

## 1. 検証の順序

1. Binance等の既存RAWデータで、1M観測を基準に5M/10M Episodeの構造を比較する。
2. 構造検証の条件を変更せず、HFMで手動実測する。
3. 実測後にのみ、HFMのスプレッド・約定遅延・セッション差を集計する。

構造検証は利益証明ではない。HFM実測は、記録されたシグナル・見送り・拒否を含めて評価し、約定結果だけを抽出しない。

## 2. 固定する観測条件

- シグナル時刻は受信時刻（UTC）を基準にする。
- Episodeの観測窓は 60秒、300秒、600秒を並列に出力する。
- 将来リターンの評価窓は 300秒、600秒とする。
- 欠損、時刻逆行、データギャップ、非正価格は有効結果に含めないが、除外件数は必ず報告する。
- 1Mコア、Flow Price Response、3段チャートのロジックは変更しない。

## 3. 固定セッション区分（UTC）

シグナル時刻を次の排他的な区分に分類する。境界は変更しない。

| UTC | session_id |
|---|---|
| 00:00–07:59 | ASIA |
| 08:00–12:59 | EUROPE |
| 13:00–16:59 | EUROPE_NY_OVERLAP |
| 17:00–21:59 | NEW_YORK |
| 22:00–23:59 | LATE |

HFMのブローカー時刻は、オフセットを推測して直接区分しない。まず同一ローカル時刻をUTCへ正規化できた記録だけを分類する。正規化できない記録は `SESSION_UNKNOWN` として別集計する。

## 4. 出力する指標

- Episode段階別件数、完了率、無効化率、未解決率
- 60/300/600秒での段階遷移の一致・不一致
- 将来リターン、pressure_signed_return、MFE、MAE
- データギャップ率、結果欠損率
- HFMではスプレッド、約定遅延、見送り率、約定後損益
- 上記を全体および `session_id` 別に出力

## 5. 判定ルール

最初の集計は探索結果として扱い、件数不足で優位性を主張しない。5M/10Mが1Mの注文フロー特性を保持しているか、HFMコスト控除後にも再現性があるかを別々に判定する。自動発注への移行は、この二つの判定が完了するまで行わない。

この文書制定後、セッション区分・窓・指標を結果に合わせて変更しない。変更が必要な場合は、旧プロトコルを無効化せず改訂版として別日付で記録する。
