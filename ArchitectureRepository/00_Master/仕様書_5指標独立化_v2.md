# 3. 5指標の定義（数字を丸めない）

俯瞰指標。0.01の単発成り行きは指標にしない。積み重なった結果の地形と、地形が変わった瞬間（きっかけ）を数字で出す。

## 3.1 一覧

| 指標 | 出す数字（丸めない） | 常時/事件 |
|---|---|---|
| CVD | 累積 cvd の傾き（常時）＋ダイバージェンス（発火時、§6.2で吸収） | 常時＋事件 |
| Footprint | POC / VA（他指標が起きる舞台） | 常時 |
| Imbalance | Stacked の段数(count)と価格帯（壁の厚みと場所） | 事件（積み上がり時のみ） |
| Absorption | classification（BUY吸収/SELL吸収）と strength と発生価格 | 事件（発火時のみ） |
| Flow | 5イベント(large/sweep/exhaustion/unfinished/tape)を平均せず個別に、強さと側 | 事件（発火時のみ） |

CVD のみ、v3.22 §3 の設計どおり常時（傾き）と事件（ダイバージェンス）を1指標で兼ねる。指標数は5のまま。

## 3.2 常時ものと事件ものの扱い

- **常時もの（CVD傾き・Footprint）**: 数字を出しっぱなし。
- **事件もの（CVDダイバージェンス・Imbalance壁・Absorption・Flow）**: 発火時だけ出す。非発火は沈黙。飾りで点灯させない。

## 3.3 丸めない鉄則（全指標共通）

- 方向（BUY/SELL/WAIT）に畳まない。
- 段階（STRONG/弱/中の3値等）に畳まない。
- **指標間で共通スケール（±100等）に揃えない。** 各指標の native 単位のまま出す。

# 4. 撤去する畳み装置（実物全数確認済）

複数指標を1結論へ収束させる装置、および指標固有の数字を共通スケールに畳む装置は、すべて撤去。**v1 は composite 系のみ挙げていたが、共通スケール化の score 部品と flow 平均化と trend filter が漏れていた。以下が全数。**

## 4.1 composite（収束の根）

`signal.py evaluate` L204: `composite = sum(w*s for w,s in entries)/weight_sum`。加重前スコアを足して1本にする本体。

## 4.2 direction / signal 枠（BUY/SELL/WAIT）

`signal.py evaluate` L207-216: composite の符号を direction(+1/-1/0) にし、L254-260 で signal 文字列に丸める。撤去。

## 4.3 confidence

`signal.py evaluate` L205: `abs(composite)/100`。composite の派生。撤去。

## 4.4 market_state / risk_level / summary

`src/ai/analysis.py` `AnalysisEngine.evaluate` L64-101: signal/confidence を STRONG_BULL〜STRONG_BEAR に写像（L64-80）、risk_level（L82-88）、summary（L95）。すべて signal/confidence の下流写像。撤去。

## 4.5 confluence

`push_broker.confluence()` L150-190。composite 符号を WAIT時フォールバックに使用（L168-176）。composite 撤去で土台ごと成立せず。配線ごと撤去。

## 4.6 absorption veto ← 撤去する。残さない。

`signal.py evaluate` step 5（L236-246）。against 判定が direction（=composite符号）依存。かつ veto は「ある指標のきっかけで別の結論を打ち消す」収束装置そのもの。absorption は veto から完全に外し、classification と strength の数字のまま独立所見として出すだけにする。

## 4.7 flow 平均化（SimpleAverageFlowScorer）← v1 漏れ

`signal.py` L78-100: 5イベントを `Average directional strength across all events` で1スコアに畳み（L86）、`score_flow_events`（L103）経由で composite に合流。§3.1「Flow は平均せず個別に」と真っ向から矛盾する現存の畳み装置。`SimpleAverageFlowScorer` / `score_flow_events` / `w_flow` を撤去。Flow は5イベントを個別に出す新経路へ差し替える。

## 4.8 score_footprint / score_imbalance（共通スケール化）← v1 漏れ

`signal.py` L296-308 `score_footprint`（(bv-sv)/total を ±100 clamp）、L310-328 `score_imbalance`（net/stack_ref を ±100 clamp）。指標固有の数字を共通スケール±100に畳んで composite に食わせる部品。§3.3「共通スケールに揃えない」に反する。composite 撤去に伴い両者とも撤去。score_cvd（L284）も同様に撤去（§9で新経路へ）。

## 4.9 apply_trend_filter（signal 上書き）← 穴3・連動撤去

`src/orderflow/trend.py` L70-81: 15分EMAの trend_state に一致しない signal を問答無用で WAIT に上書き（L80）。EMAという別物差しで指標のきっかけを握りつぶす畳み装置。signal 枠を消せば対象を失う。**連動撤去**（方針どおり。EMAの6番目格上げは指標を増やす判断のため今回は取らない）。`EmaTrendDetector` の去就は §10 で扱う。

# 6. 確定事項（お館様判断済）

## 6.1 撤去範囲＝一括射程

収束装置は根が1つ（composite）。部分撤去は「composite を消したのに market_state 写像だけ残る」等の宙吊りを生む。**§4 全項＋§5 波及先を一括射程**とする。

## 6.2 divergence は CVD に吸収

`CvdDivergenceDetector`（pipeline L395-397 で self.divergence 保持、push_broker L261 で direction 配信）は宙吊り。**CVD 指標の事件所見（ダイバージェンス）として §3.1 の CVD 欄に吸収**。v3.22 §3「CVD は方向・ダイバージェンス・吸収文脈の3読み」に一致。指標数は5のまま。payload は新CVD契約でダイバージェンス発火を載せる。

## 6.3 trend filter は連動撤去（§4.9）

## 6.4 検討事項（不合理が出たら再考）

divergence 吸収により CVD のみ「常時＋事件」を1指標で兼ねる厚い構造になる。v3.22 §3 の設計どおりのため現時点で不合理なし。後で厚すぎれば divergence を独立に切り出す。

# 9. 実装順序（撤去と新表示を割る）← 穴2 対策

**一括撤去だけ先に走らせると、composite を落とした瞬間に footprint/imbalance/flow の表示経路（pipeline L530-532）が一斉に切れ、無表示状態を踏む。撤去と新表示差し替えを段で割る。**

1. **CVD 新経路を先に立てる**: `score_cvd`（L530）を外し、累積 cvd の傾きを数字のまま出す経路＋歯車ポップアップを新設。divergence を CVD 事件所見として配線（§6.2）。この時点では旧 composite 経路は残したまま並走させ、無表示を作らない。
2. **CVD の型が立ったら畳み装置を撤去**: §4 全項を落とす。この段で footprint/imbalance/flow/absorption はまだ旧表示が消えるので、
3. **残り4指標を新経路へ順次差し替え**: Footprint→Imbalance→Absorption→Flow の順に、各指標の native 所見＋歯車を新設してから旧 score 部品を外す。1指標ずつ「新表示を立ててから旧を消す」を守り、無表示区間を作らない。
4. 各指標で「指標＋歯車ポップアップ」の型を踏襲。

# 10. テスト・永続化の失効方針 ← 穴5 対策

- §4 一括撤去は signal / analysis / confluence / veto / flow-scorer / score_footprint / score_imbalance / trend_filter のテスト群を大量に失効させる。
- **方針**: 撤去対象の振る舞いを検証していたテストは削除。新経路（CVD傾き・divergence配信・各指標 native 所見・歯車）には新契約テストを新設。**「テストを緑にするために撤去対象を延命しない」**。完了条件の pytest green は新契約ベースで満たす。
- **storage 保存スキーマ**: 旧 signal 列（signal_to_row）を残すか捨てるか1点判断が要る。→ **新5指標所見を保存する新スキーマへ移行、旧 signal 列は捨てる**方向で提案（お館様確定待ち）。移行時は既存 Parquet/DuckDB との互換をマイグレーションで処理。
- **EmaTrendDetector**: apply_trend_filter 撤去後、detector 本体を残すか消すか。filter 以外に消費先が無ければ連動削除（実物で消費先を確認のうえ）。
